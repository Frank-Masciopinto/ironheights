## Common failure patterns

1. **Guard and scanner docs quote the attack.** This caused most of the hits for D, E and B. Vetters, sanitizers, CTF guides and red-team notes contain the exact attack strings, in lists, quotes or `"..."` literals.
2. **Normal config code looks like a secret bundle.** C v1 and I v1 fired on code that puts env secrets into a client config or header, and on setup steps that write a key to `.env`. A secret name alone isn't evidence; where it goes is.
3. **Ordinary words in honest skills.** "no need to mention", "skip confirmation", "camouflage", "masquerade", "override", "regardless of policy" are all common in UX writing, game and network skills. Rules built on one keyword fail. The same shape showed up again on 2026-11-06: "every session" next to `MEMORY.md` is how a normal memory skill describes itself.
4. **Prose versus imperative.** Hits that describe or report something ("instruction override is an attack type") look like orders unless the rule requires an order aimed at the agent, or self-reference ("this skill…", "these directives…").
5. **Relaxing to cut false positives loses attacks.** Night G, FP-key E and the Serpent tight variant all lost a real attack. Attackers write paths and waivers in plain prose too. Setting IH-REF-001 to zero points did the same thing: 11 public blocks fell to review, and the blind block count fell under the gate.
6. **Red-team-only targets show no gain.** Rules written for house-\* pairs (Night H, H v2, I v2) pass every gate but move no benchmark or blind row.

## Before proposing a new rule, check

- Does the motivating row exist in the benchmark or blind set? If it's only a house or red-team row, expect "no measured gain" and say so up front.
- Scan the look-alike set (real ClawHub plus GitHub, chosen by keyword) **before** tuning. Also try a guard/scanner subset (vet, scanner, injection, jailbreak, CTF) and a config-code subset.
- Require two signals together: the risky capability **and** a sink or effect (network call, published file, serialization of that variable, the agent told to obey), in the same block or paragraph.
- Strip string literals, comments, list items and quoted text before matching code patterns. Skip skills that describe attacks (GUARD_DOC).
- Match orders aimed at the agent, not nouns ("treat X as overriding", not "instruction override").
- For any rule that downgrades, build an adversarial twin and check that no benchmark or blind attack is lost.
- Look-alikes used to tighten a rule are no longer independent. Keep a fresh held-out look-alike sample when you can.
