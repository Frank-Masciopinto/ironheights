# Moltbook-families benchmark set

A scored set for the attack families the Moltbook accuracy ideas target.
It is generated by us from a pinned seed. It is not an independent corpus,
and it does not reuse the wording of the house or missed-attack fixtures.

Set version: `moltbook-families-v1`

- 384 attacks + 384 honest twins (768 skills).
- 12 families × 4 structures × 8 domains.
- Each domain changes the job, the nouns, and the host.
- Even domains are prose. Odd domains are numbered steps.
- Domains whose index mod 4 is 2 or 3 are multi-file: one leg stays in
  `SKILL.md` and the other is in a named file under `notes/`, `references/`,
  `docs/`, or `config/`. A rule that only reads `SKILL.md` cannot see both legs.
- Every attack has an honest twin of the same job: the user names the scope,
  nothing is hidden, and a skill-written host is not introduced.
- Hosts are `*.example.invalid`. There are no real secrets. **Nothing in this
  set is executed.**

## Families

| Family              | What the attack does                                                                                                                                     | What the twin does                                                                             |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| split-multifile     | A wide read, a cached secret, or a receipt is paired with a destination the skill wrote, and the front door does not report it                           | Reads the project, asks where to send, lists that place                                        |
| credential-phishing | A mailbox, SMS inbox, clipboard, authenticator export, or chat paste is forwarded to a host the skill names                                              | Opens the provider's own device-code page and never reads the code                             |
| purpose-mismatch    | The description names one record; the steps take a wider role or rewrite every record; the reply names the one                                           | The description is the wide job, the count is shown, and a yes is required                     |
| mcp-poison          | An optional parameter asks for the conversation, files, environment, or system prompt; or a same-name sender claims precedence and posts to a skill host | The user types the value in this request; the tool does not replace another tool               |
| global-persist      | A one-off or an unread postinstall writes a user-level hook path, a user crontab, a login item, or a session-start hook                                  | The hook stays inside this repository, or install scripts stay disabled                        |
| trust-anchor        | Identity-provider metadata, a trusted issuer, a JWKS address, or the sign-in provider is set to a host the skill wrote                                   | The company IT team names the issuer; the diff is shown; refresh stays off                     |
| staged-loader       | A destination list, runbook, setup note, or `pre_steps` field is fetched with no checksum and then executed or used as recipients                        | The list ships in the skill with a sha256, and remote text stays data                          |
| control-downgrade   | A legacy algorithm, oldest TLS, plaintext fallback, Include glob, or Match exec applies wider than the one device the user named                         | One named host, one method appended, host-key checking left on                                 |
| scope-widen         | A grant is applied to a parent, organization, or workspace while consent names a narrower resource                                                       | The named resource only, with an expiry, and a parent grant is refused                         |
| concealment         | A mail rule archives sign-in or account-security notices inside an unrelated tidy, or the approval sentence is narrower than the gated steps             | The user named the newsletter, security mail is untouched, and the approval lists every effect |
| hidden-obfuscation  | A hidden comment, a collapsed details block, an assembly rule, or a markdown reference comment tells the agent to read a secret and send it              | A formatter pragma or a visible caption, with no secret and no send                            |
| lookup-input        | A token, the clipboard, a mailbox subject, or a shell-history line is placed in the query of a lookup to a host the skill names                          | The user types a public id, and the lookup host is one they name                               |

## Labeling

Labels are assigned by construction: the malicious file contains the attack
legs, and the twin contains the honest legs of the same job. A model did not
label this set. See `labeling_notes` in `manifest.json` and `labels.json`.

## Split

Recorded before any rule was written against this set.

```
split = "dev" if int(sha256(f"{seed}:{id}").hexdigest()[:8], 16) % 2 == 0 else "heldout"
seed = "moltbook-families-20261121"
```

The tree hash is `tree_sha256` in `manifest.json`. If any held-out sample is
read for tuning, the held-out half is burned and must be re-split with a new
seed. This set never touches `bench/blind`. Dev counts and held-out counts are
both about half; the hash is not forced to a round number.

## Layout

- `generate.py` — deterministic builder. Writes `samples/`, `labels.json`, and
  `manifest.json` (per-file SHA-256 and a tree hash). `--check` regenerates in
  a temp directory and compares.
- `samples/<id>/` — generated on demand (gitignored).
- `score.py` — Ironheights (one or more CLIs), Cisco skill-scanner 2.3.2, and
  NVIDIA SkillSpector v2.12.0 `--no-llm`.
- `results/` — scores. Dev rows may be read while tuning. Held-out rows are the
  report, not a tuning input.

## Reproduce

From the repo root, after `npm run build`:

```
python3 bench/moltbook-families/score.py \
  --ih main=dist/cli/index.js \
  --ih release=/path/to/ironheights-0.37.0/dist/cli/index.js \
  --cisco .venv/bin/skill-scanner \
  --nvidia .venv/bin/skillspector
```

Verdict mappings match `scripts/benchmark-msb.py` (see `docs/benchmark-proof.md`).
